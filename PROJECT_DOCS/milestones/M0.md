# M0 — Foundation

> Status: **Completed**
> Size: S · Depends on: —
> Covers: `CLI-1` (basic), `CLI-5..7`, `RCV-5`, `SEC-7`, `NFR-2`

## Goal

A repository where everything later can be built, tested, and shipped. `make ci` green on macOS and Linux; `garagefab start` serves a placeholder UI and `/api/health`.

## Dependency Graph

```
T1 (repo setup)
├── T2 (CI) ← needs Makefile and go.mod
├── T3 (config) ← needs go.mod
├── T4 (store) ← needs go.mod
```

> [!NOTE]

> all code exists is simpler for a Size S milestone.

## Tasks

### T1 — Repository Setup

**Requirements:** `NFR-2` (CGO_ENABLED=0 build)
**Artifacts:** `go.mod`, `Makefile`, `.gitignore` (updated), `README.md` (updated)

**What to do:**

1. Initialize Go module: `go mod init github.com/garagefab/garagefab` (Go 1.22+).
2. Create `cmd/garagefab/main.go` with a minimal `func main()` that prints "garagefab" (enough for `go build` to pass).
3. Create `Makefile` with targets:
   - `build`: build UI then `CGO_ENABLED=0 go build -o bin/garagefab ./cmd/garagefab`
   - `test`: `go test ./...`
   - `lint`: `golangci-lint run`
   - `vet`: `go vet ./...`
   - `ui`: `cd ui && npm ci && npm run build`
   - `ci`: `lint` + `vet` + `test` + `build` (UI build is a prerequisite of `build`)
   - `dev`: run `garagefab start` with reloading (optional, can be added later)
4. Update `.gitignore`:
   ```
   bin/
   ui/dist/
   ui/node_modules/
   .DS_Store
   *.db
   *.db-wal
   *.db-shm
   ```
5. Update `README.md` with a brief description, build prerequisites (Go 1.22+, Node 20+, git 2.30+), and quick-start instructions (can be placeholder).
6. Create the package directory structure (empty `.go` files with just the `package` declaration, or no files — directories are created as tasks fill them):
   ```
   cmd/garagefab/
   internal/config/
   internal/store/
   internal/server/
   ```

**Acceptance:**
- `go mod tidy` succeeds.
- `CGO_ENABLED=0 go build -o bin/garagefab ./cmd/garagefab` produces a static binary.
- `make build` completes (UI step may be a no-op until T7).

### T3 — Config (`internal/config`)

**Requirements:** `CLI-6`, `SEC-7`
**Artifacts:** `internal/config/config.go`, `internal/config/config_test.go`

**What to do:**

1. Define the `Config` struct (architecture §14, global config only for M0):
   ```go
   type Config struct {
       Server  ServerConfig
       Engine  EngineConfig
       GitHub  GitHubConfig
   }
   type ServerConfig struct {
       Listen   string // default "127.0.0.1:7878"
       APIToken string
   }
   // EngineConfig and GitHubConfig with defaults only — 
   // fields needed by later milestones are present but not used yet.
   ```
2. `Load(dataDir string) (*Config, error)`:
   - If `dataDir` is empty, default to `~/.garagefab`.
   - If the directory doesn't exist, create it with `0700`.
   - If `config.yaml` doesn't exist, generate it with a random API token (32-byte hex via `crypto/rand`), write with `0600`.
   - If `config.yaml` exists, load and validate:
     - `server.listen` must be a loopback address (rejects `0.0.0.0`, non-loopback IPs).
     - API token must be non-empty.
   - Check and warn if permissions are too permissive (directory not `0700`, file not `0600`).
3. YAML parsing: use `gopkg.in/yaml.v3` (or `sigs.k8s.io/yaml` — decide and add to decision log).

**Acceptance:**
- `CLI-6`: Given an empty home, after `Load()`, the directory is `0700`, `config.yaml` is `0600`, and contains a generated token.
- `SEC-7`: Given a directory with mode `0755`, `Load()` logs a warning.
- Given `server.listen: "0.0.0.0:7878"`, `Load()` returns a validation error naming the field.
- Given a valid config, the returned struct has the expected values.

### T4 — Store (`internal/store`)

**Requirements:** (foundation for all later milestones; `NFR-7` baseline)
**Artifacts:** `internal/store/db.go`, `internal/store/migrations/0001_init.sql`, `internal/store/db_test.go`

**What to do:**

1. `Open(dbPath string) (*DB, error)`:
   - Open SQLite with `modernc.org/sqlite`.
   - Apply PRAGMAs (architecture §5): `journal_mode=WAL`, `busy_timeout=5000`, `synchronous=NORMAL`, `foreign_keys=ON`.
   - Separate write connection (serialized) and read pool.
   - Run migrations via `pressly/goose` with embedded SQL files.
2. Migration `0001_init.sql`:
   - M0 only needs a minimal schema to prove the migration system works. Create a `_meta` table:
     ```sql
     CREATE TABLE _meta (
         key   TEXT PRIMARY KEY,
         value TEXT NOT NULL
     );
     INSERT INTO _meta (key, value) VALUES ('schema_version', '1');
     ```
   - The real schema (projects, jobs, steps, events, etc.) grows in M1.
3. `Close()` that cleanly shuts down connections.
4. Schema version check: on startup, verify the schema is not newer than what the binary expects (`CLI-7`).

**Acceptance:**
- Migrations apply cleanly on a fresh database.
- A parallel reader test: one goroutine writes while another reads — no "database is locked" errors (`NFR-7` baseline).
- `Close()` is clean (no leaked connections).
- Given a database with schema version 99, `Open()` returns an error (`CLI-7` partial).

### T5 — Single-Instance Lock File

**Requirements:** `RCV-5`
**Artifacts:** `internal/config/lockfile.go`, `internal/config/lockfile_test.go`

> [!NOTE]
> Placed in `internal/config` because it operates on the data directory.
> Could also be a separate `internal/lockfile` package — decide during implementation.

**What to do:**

1. `AcquireLock(dataDir string) (Releaser, error)`:
   - Create/open `<dataDir>/garagefab.lock`.
   - Use `syscall.Flock` (LOCK_EX | LOCK_NB) on Unix.
   - On failure, return an error message naming the lock file path (so the user knows another instance is running).
   - Return a `Releaser` interface with `Release() error` that unlocks and closes the file.
2. Lock is released on `Close()` or process exit.

**Acceptance:**
- `RCV-5`: Given a running lock holder, a second `AcquireLock()` fails with a descriptive error.
- After `Release()`, a new `AcquireLock()` succeeds.

### T6 — Cobra CLI

**Requirements:** `CLI-1` (basic), `CLI-5`, `CLI-6`, `CLI-7`
**Artifacts:** `cmd/garagefab/main.go` (updated), `internal/server/server.go`, `internal/server/health.go`

**What to do:**

1. Set up `spf13/cobra` with root command and subcommands:
   - `version`: prints version, commit SHA, and build date (injected via `-ldflags`). Update `Makefile` to pass these.
   - `start [--port N] [--data-dir PATH] [--no-open]`:
     1. Load config (`T3`).
     2. Acquire lock (`T5`).
     3. Open store and run migrations (`T4`).
     4. Run startup checks (`CLI-7`):
        - `git` available: run `git --version`, parse version ≥ 2.30.
        - Port free: attempt to listen; fail with a clear message if EADDRINUSE.
        - Schema version not newer than binary (from `T4`).
     5. Start HTTP server (chi router) on `config.Server.Listen`:
        - `GET /api/health` → `{"status": "ok"}` (no auth required).
        - Static file handler for embedded UI (`T7`).
     6. Print the dashboard login URL: `http://127.0.0.1:<port>/login#token=<api_token>`.
     7. Open browser unless `--no-open` (use `open` on macOS, `xdg-open` on Linux).
     8. Block on signals (SIGINT, SIGTERM); on signal, shut down gracefully.
2. Server setup in `internal/server`:
   - `NewServer(cfg *config.Config, db *store.DB) *Server`
   - Chi router with `middleware.RequestID`, `middleware.Logger`, `middleware.Recoverer`.
   - Auth middleware stub (for M0: only `/api/health` exists, auth is not enforced yet — placeholder middleware that will be completed in M1).
   - Host header check: reject if `Host` is not `127.0.0.1:<port>` or `localhost:<port>` (`SEC-2` — implement now since it's cheap).

**Acceptance:**
- `CLI-5`: `garagefab version` prints version, commit, and build date.
- `CLI-1` (basic): `garagefab start` serves `/api/health` returning `{"status": "ok"}`.
- `CLI-6`: First start creates data dir, config, and database.
- `CLI-7`: Given `git` not in PATH, startup fails. Given a busy port, startup fails. Each failure is one clear message on stderr with a non-zero exit.
- `RCV-5`: Given a running instance, a second `garagefab start` exits with a message naming the running instance.
- Graceful shutdown on SIGINT.

### T7 — Embedded UI Placeholder

**Requirements:** (foundation for `UI-*` in M4)
**Artifacts:** `ui/` directory (Vite + React + TypeScript + Tailwind CSS 4 + shadcn/ui), `internal/server/embed.go`

**What to do:**

1. Initialize the UI project in `ui/`:
   - `npm create vite@latest . -- --template react-ts`
   - Install Tailwind CSS 4 and shadcn/ui.
   - Configure `vite.config.ts` with `base: '/'` and `build.outDir: 'dist'`.
2. Create a single placeholder page (`App.tsx`):
   - Display "Garagefab" as a heading.
   - On mount, fetch `GET /api/health` and display the result (e.g., "Service: OK" with a green indicator, or "Service: unreachable" with a red one).
   - Minimal styling with Tailwind.
3. Embed in Go:
   - `internal/server/embed.go`:
     ```go
     //go:embed all:ui/dist
     var uiFS embed.FS
     ```
     Wait — this won't work because `ui/dist` is not under `internal/server`. Two approaches:
     - **Option A:** The embed directive is in `cmd/garagefab/` or a top-level package and passed to the server.
     - **Option B:** A build step copies `ui/dist` into `internal/server/ui/dist`.
     - **Recommended: Option A.** The `//go:embed` lives in `internal/server/` with a relative path `../../ui/dist`. Actually, `//go:embed` only works with paths relative to the source file and within the module. So the embed must be at the package whose directory contains or is a parent of `ui/dist`.

     **Solution:** Place the embed in a dedicated `internal/server/ui.go` or at `cmd/garagefab/embed.go` and pass the `fs.FS` to the server constructor. Going with `cmd/garagefab/` for now — the server receives an `fs.FS` in its constructor.
4. SPA fallback: serve `index.html` for any non-API, non-asset path.
5. Update `Makefile`:
   - `ui` target: `cd ui && npm ci && npm run build`.
   - `build` depends on `ui`.

**Acceptance:**
- `make ui` produces `ui/dist/index.html`.
- `make build` embeds the UI into the binary.
- `garagefab start --no-open` → browser at `http://127.0.0.1:7878` shows the placeholder page with the health status.
- The binary works without Node.js at runtime (embedded static files).
