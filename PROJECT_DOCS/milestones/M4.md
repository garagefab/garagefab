## Tasks

> [!NOTE]
> **Medium Detail Level:** This milestone is further out. Tasks should be detailed further when this milestone becomes next.

### T1 — Login Flow and CLI `open`
**Requirements:** `SEC-3`, `CLI-2`
**What to do:**
- Implement `garagefab open` to print and open a new login URL (`http://127.0.0.1:<port>/login#token=<api_token>`).
- Implement the UI login page that extracts the token fragment, posts to `/api/session`, and removes the fragment with `history.replaceState`.
- Implement the session cookie response (`HttpOnly`, `SameSite=Strict`) in the server.
**Acceptance:**
- `CLI-2`: `open` restores access with a fresh URL.
- `SEC-3`: `/api` routes require a session cookie or bearer token. UI uses the cookie.

### T2 — Overview Screen
**Requirements:** `UI-1`
**What to do:**
- Build the Overview page displaying: job counts per status, a recent activity feed, an "attention" list, intake/provider errors, and orphan worktrees.
**Acceptance:**
- `UI-1`: Counts match the database; attention items link to their respective jobs.

### T3 — Project Board / Kanban
**Requirements:** `UI-2`
**What to do:**
- Build a read-only Kanban board showing the 7 stage columns.
- Render cards with title, work type, job ID, and a status indicator.
**Acceptance:**
- `UI-2`: Cards appear in the correct columns based on stage; a running indicator is shown when appropriate. No drag-and-drop capability.

### T4 — Forms (Project & Job)
**Requirements:** `UI-6`, `PRJ-1..8`, `INT-1`
**What to do:**
- Create "Add Project" form accepting a repository path.
- Create "New Job" form accepting project, work type, title, and intent text fields.
- Integrate inline validation using API responses.
- Implement "Create template" for `project.yaml`.
**Acceptance:**
- `UI-6`: Invalid input (e.g. invalid path) shows an inline error next to the field.
- `PRJ-1`: Registered project appears in the project list.
- `INT-1`: Job created from UI appears at `01_Intent`/`queued`.

### T5 — Task Detail Page & Pipeline Viz
**Requirements:** `UI-3`, `UI-8`, `UI-9`, `HND-1`, `SPC-8`
**What to do:**
- Build the job detail page.
- Add pipeline visualization showing the steps of the profile with their state.
- Display the evidence summary and drill-down links.
- Render the `spec.md` as Markdown for jobs in `spec_review`.
- Render a copy button for the handoff command.
- Add a warnings badge.
**Acceptance:**
- `UI-3`: Steps show correct state (complete, running, pending).
- `UI-8`: ⚠️ badge shows warning count.
- `HND-1`: Handoff command copied correctly.
- `SPC-8`: Spec rendered as Markdown.
- `UI-9`: Large diffs truncated with "show more" control.

### T6 — Action Forms
**Requirements:** `UI-4`
**What to do:**
- Add action buttons (Approve, Reject, Retry, Cancel) to the task detail page.
- Ensure they are dynamically enabled only when valid for the job's current status.
- Wire Reject to display a form to prompt for a required note.
**Acceptance:**
- `UI-4`: Buttons enabled only when valid (e.g., Cancel for `running`, Approve for `spec_review`).

### T7 — Live Updates & Log Viewer
**Requirements:** `UI-5`, `UI-7`, `LOG-5`
**What to do:**
- Implement an SSE client in the UI listening to `/api/events`.
- Update state in the UI (cards, pipeline, activity feed) upon receiving events without full page reload.
- Build the Log Viewer component: streaming for active steps, and on-demand loading of stored files for finished steps.
**Acceptance:**
- `UI-5`: Status changes reflect in UI within 1s.
- `UI-7`: Logs stream for running steps; finished steps load stored files.
- `LOG-5`: Logs are not fetched until the viewer is explicitly opened.

### T8 — Keyboard Accessibility
**Requirements:** `NFR-8`
**What to do:**
- Perform a manual keyboard-only pass on all UI components.
- Verify text contrast meets WCAG 2.1 AA.
- Ensure status is conveyed through text or icons, not color alone.
**Acceptance:**
- `NFR-8`: UI can be fully navigated and operated by keyboard. Contrast checks pass.
