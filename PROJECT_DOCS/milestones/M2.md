## Tasks

> [!NOTE]

### T1 — Failure Categorizer
**Requirements:** `COD-4`
**What to do:** Implement the pure function in `factory` to categorize deterministic step failures (Flawed, Blocked, Manual) based on exit codes, timeouts, and output.
**Acceptance Criteria:**
- Given a non-zero exit from test/build/lint, returns Flawed.
- Given a command timeout, returns Blocked.
- Given attempts exhausted, returns Manual.

### T2 — Repair Loop
**Requirements:** `COD-3`, `COD-5`, `COD-6`, `COD-7`, `COD-10`
**What to do:** Integrate the failure categorizer into the pipeline engine. When a step is Flawed and attempts remain, re-run the coding agent with the error output. Re-run all command steps after repair. Handle agent timeouts and empty changes.
**Acceptance Criteria:**
- Given a failing test and attempts left, the coding agent is re-run with failure output.
- Given a repaired lint failure, build and test run again.
- Given an agent that exits 0 without editing files, step is Flawed.
- Given an agent that hangs, process group is terminated and failure is Blocked.

### T3 — Guardrails
**Requirements:** `GRD-1..4`
**What to do:** Implement the `protected_paths` guardrail in `worker/command`. Run it after every agent step that changes code. Also implement custom command guardrails.
**Acceptance Criteria:**
- Given pattern `**/*_test.go` and an agent edits `a_test.go`, guardrail fails and lists file.
- Given a new `b_test.go`, guardrail passes.
- Given a violation, step is Flawed once per attempt, and repair prompt names files.
- Given a custom command that exits 1, step is Flawed with its output.

### T4 — Cancel and Retry (Pipeline & Worktree)
**Requirements:** `PIP-6/7`, `WKT-5/7/8`
**What to do:** Implement Cancel and Retry actions. Cancel terminates the process group and removes the worktree. Retry resets the worktree to the step-start checkpoint and re-runs the step. Handle leftover branches and orphan worktrees.
**Acceptance Criteria:**
- Given a running job, when cancelled, process group receives SIGTERM then SIGKILL, status becomes cancelled, worktree is removed.
- Given a failed/interrupted job, when Retry is clicked, job returns to queued and step runs again from last checkpoint.
- Given an interrupted coding step with half-written files, Retry resets the worktree.
- Given a leftover branch `garagefab/job-<id>`, job fails with a clear message.
- Orphan worktrees are listed on the Overview for manual cleanup.

### T5 — Crash Recovery
**Requirements:** `RCV-1..4`
**What to do:** Record process group info (pid, pgid, start time) before reading output. On startup, check for active processes from previous runs and terminate them. Mark affected jobs as interrupted. Handle graceful shutdown (SIGINT/SIGTERM).
**Acceptance Criteria:**
- Started step has a process record.
- Surviving fake agent from a simulated crash is killed at next start (PID/start time match).
- After crash during coding, job is interrupted and waits for Retry/Cancel.
- Ctrl+C with running jobs sends SIGTERM/SIGKILL, terminates children, and marks jobs interrupted.

### T6 — Concurrency Limits & Security
**Requirements:** `SCH-2/5`, `SEC-6`
**What to do:** Enforce project-level concurrency limits. Allow same-project jobs to run in parallel in separate worktrees. Secure agent subprocesses by passing only an allow-listed environment.
**Acceptance Criteria:**
- Given project limit 1, two jobs of that project never run together.
- Given two jobs touching the same file, both complete.
- Agent subprocesses receive only `PATH`, `HOME`, `USER`, `LANG`, `LC_*`, `TERM`, `SHELL`, `TMPDIR`, plus `engine.env_passthrough`.
- GitHub/API tokens are not visible to agents.

## Exit Criteria
- Spec Scenarios 3 (repair, guardrail) and 5 (crash recovery) pass in CI on macOS and Linux.
- Includes a fake agent that spawns child processes and one that ignores SIGTERM.

## Risks
| ID | Risk | Mitigation |
|----|------|------------|
| R5 | Process-group and signal behavior differs between macOS and Linux | Fake agent that spawns children; CI on both platforms |
| R11 | Timing-based process tests are flaky | Synchronize on events rather than sleeps; repeat runs in CI |
