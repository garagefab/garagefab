# Garagefab Work

You are assisting a developer with a paused Garagefab software factory job.
Your task is to inspect the job state, review relevant artifacts, interact with the developer, and guide next steps.

## Workflow

### 1. Read Job Details
Run the API helper script from this skill's scripts directory:
```sh
scripts/gf-api.sh GET /api/jobs/<job-id>
```
Inspect the returned JSON payload:
- `stage`: Current stage number (e.g. `02`, `04`, `06`).
- `status`: Current job status (`needs_clarification`, `spec_review`, `awaiting_approval`, `failed`, `interrupted`).
- `worktree_path`: Absolute path to the isolated git worktree for this job.
- `title`, `work_type`, `intent`: Job intent and scope.

### 2. Fetch Job Artifacts & Logs
Fetch relevant artifacts as needed:
```sh
scripts/gf-api.sh GET /api/jobs/<job-id>/artifacts/<name>
```
Allow-listed artifact names:
- `intent` (original user intent)
- `clarification-questions` (open questions generated by the spec stage)
- `clarification` (previous clarification Q&A history)
- `spec` (current specification markdown)
- `review` (review findings JSON from stage 05)
- `evidence` (chain-of-evidence summary)

If the job status is `failed` or `interrupted`, inspect the step execution history and latest error log:
```sh
scripts/gf-api.sh GET /api/jobs/<job-id>/steps
scripts/gf-api.sh GET /api/jobs/<job-id>/steps/<step-id>/log
```

### 3. Switch to Worktree
Change your working directory into `worktree_path` and operate **only inside this worktree**:
```sh
cd <worktree_path>
```
Do not modify files in the main repository.

### 4. Handle Status-Specific Scenarios

#### Scenario A: `needs_clarification` (Stage 02)
1. Read the generated clarification questions:
   ```sh
   scripts/gf-api.sh GET /api/jobs/<job-id>/artifacts/clarification-questions
   ```
2. Present each question clearly to the developer and discuss their answers.
3. Once all answers are decided, submit the structured clarification via the API:
   ```sh
   scripts/gf-api.sh POST /api/jobs/<job-id>/clarification '{"answers":[{"q":1,"answer":"..."},{"q":2,"answer":"..."}]}'
   ```
4. This automatically appends the answers to `clarification.md` and re-queues Stage 02 for the agent to incorporate them.

#### Scenario B: `spec_review` (Stage 02)
1. Inspect the generated specification:
   `<worktree_path>/.garagefab/jobs/<job-id>/spec.md`
2. Review the spec requirements, acceptance criteria, and plan with the developer.
3. If changes are needed, edit `<worktree_path>/.garagefab/jobs/<job-id>/spec.md` in place directly in the worktree.
4. **DO NOT** run `git commit`.
5. Instruct the developer to click **Approve** in the Garagefab web dashboard.
   (The server re-reads and re-validates the edited spec from the worktree upon approval).

#### Scenario C: `awaiting_approval` (Stage 06)
1. Review the git diff and verification evidence with the developer:
   ```sh
   scripts/gf-api.sh GET /api/jobs/<job-id>/diff
   scripts/gf-api.sh GET /api/jobs/<job-id>/evidence
   ```
2. Guide the developer on what changed and whether test/lint suites passed.
3. Instruct the developer to click **Approve** or **Reject** in the web dashboard.
   (To prevent accidental or automated gate bypasses, approval/rejection strictly requires interactive dashboard session authorization).

#### Scenario D: `failed` (Any Stage)
1. Fetch the steps list and examine the failed step's log.
2. Investigate the cause of the failure in the worktree with the developer.
3. If code or configuration changes are made in the worktree, test them locally.
4. Instruct the developer to use the web dashboard to retry or reset the job.

#### Scenario E: `interrupted`
1. Check the job status and steps. The job was paused due to a server restart or shutdown.
2. Inform the developer and instruct them to resume or retry the job from the dashboard.

## Security & Operational Guardrails
- **NEVER** attempt to approve, reject, cancel, or retry a job via API or scripts (`HND-5`, `APR-7`). Those actions must be performed by the developer in the web dashboard.
- The `gf-api.sh` script is restricted to `GET /api/jobs/*` and `POST /api/jobs/<id>/clarification`.
- Always keep all changes isolated within `worktree_path`.
